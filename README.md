# yuwen

`yuwen` 是一个面向低年级学生的中文汉字讲义编辑器。它把**讲义编辑**与**课堂展示**放在同一个界面里，围绕汉字、拼音、例词/例句、配图与页面式讲义组织，帮助老师/家长快速做出可讲、可练、可打印的语文材料。

本文档前半部分是**使用说明**（面向用户），后半部分是**设计与开发**（面向后续开发的出发点）。

---

# 使用说明

## 运行

原生 ES module，需通过本地服务器访问，不能用 `file://` 直接打开 `index.html`：

```bash
python3 -m http.server 5173      # 然后访问 http://localhost:5173
```

macOS 亦可双击 **「启动 yuwen.command」** 自动起服务器并打开浏览器。无需构建、无需安装依赖。讲义数据保存在本机浏览器中。

## 功能说明

### 讲义

- 顶部工具栏"讲义"面板：切换讲义；顶部有「导入」「新增」两个按钮。
- 命名、复制、导出、删除通过讲义条目的右键菜单完成（删除有确认）。
- **导出**＝把**当前选定的这一册讲义**（含图片）下载为 `yuwen-<讲义名>-<日期>.json`。
- **导入**＝从 JSON 读入并**追加为新讲义**，不覆盖现有讲义；导入后切到新讲义。

### 页面

- 左侧页面栏显示当前讲义的页面列表。
- `+` 新增页面；「导入」从 `yuwen-pages` 文件批量导入页面。
- 复制、删除通过页面条目右键菜单（删除有确认）；复制后立即切到新页面。
- 页面可拖拽重排，拖动时在目标位置显示插入指示线。

### 普通页布局

普通页固定为三块，尺寸固定、点不同字不跳版：

- **左上**：正文——字、词、句或段落。
- **左下**：当前选中字的例词/例句。
- **右侧**：当前选中字的图片；未选中字时显示当前页面配图。

### 正文编辑

- 工具栏"编辑正文 / 完成正文"切换编辑模式。
- 编辑态用中等大小文本框（非展示大字）；点空白处或失焦即提交；保留浏览器原生 `Cmd/Ctrl+Z` 撤销。

### 字号

- `A- / A0 / A+` 调节左上正文的字号，范围 0.7–1.9（`A0` 复位为 1）。
- 字号是**纯粹的字号控制**：与内容长短、普通页/全文页无关，同一档在任何页面上实际大小一致。

### 拼音

- 工具栏"拼音"开关显隐；拼音显示在字上方。
- 多音字拼音带下划线，点它弹出候选读音；单音字点无反应。
- 选择读音只改**当前这个汉字位置**的拼音。

### 汉字选择与颜色

- 左键点字＝选中；右键点字＝打开操作菜单（设色 / 清色 / 朗读单字 / 加例词句 / 加图）。
- 右键设色后，该色成为当前"连续标注色"；按住 `Option/Alt` 点其他字快速上同色。
- 同一轮连续标注中再 `Option/Alt` 点同一个字，会还原它上色前的颜色。
- 颜色面板只给少量高对比色。

### 例词与例句（左下）

- 选中字后显示该字的例词/例句；点文字进入编辑，失焦保存。
- 悬浮按钮：新增、上一条、下一条、**藏**、**删**、**提示词**。
  - "藏"只在**当前这个字位置**隐藏当前例句；"删"从讲义共享素材中删除该例句。
  - "提示词"据当前例句（或字库释义）生成一段配图提示词并复制到剪贴板，可粘到 AI 绘图工具。
- 当前选中字若出现在例句中会被标红。

### 字库例句

- 工具栏"字库例句"开关（默认关，按讲义记忆）。
- 开启后，某字**尚无任何用户例句**时，左下回落显示字库释义（带"字库"标签、只读，多条可 `‹ ›` 翻页）。
- 一旦为该字输入了自己的例句，立即切回用户例句。字库内容按"字+当前读音"选取。

### 图片与说明（右侧）

- 未选中字→当前页面配图；选中字→该字配图。
- 加图直接打开文件选择器；可删除、可在当前位置隐藏；右下小圆点可拖拽调整大小。
- 说明点按编辑、失焦保存；当前选中字出现在说明中会标红。

### 全文页

- 工具栏"全文页"开关把当前页切成整块只显示正文：无例句区、无图片区，点字不联动。
- 仍支持右键设色/清色、`Option/Alt` 连续上色、点多音字拼音切读音。适合整段展示或朗读。

### 朗读

- **单字朗读**：右键菜单"朗读"，用浏览器中文语音；普通页与全文页均可用。多音字用语音引擎默认读音（浏览器 TTS 无法可靠指定读音）。
- **整页朗读**按钮暂置灰，待发音质量改善再启用。

### 最大化（展示模式）

- 隐藏工具栏与页面栏，只留当前页。
- `← / ↑ / PageUp` 上一页；`→ / ↓ / PageDown / 空格` 下一页。
- 点"显示控制栏"退出。

### 从课本照片导入

浏览器本身不识别照片。用随仓库附带的 Claude Code 技能 `textbook-photos`：把一张/多张课本照片交给 Claude Code，它识别正文汉字（忽略照片上的拼音）、每张作一页，产出一个 `yuwen-pages` JSON；再在页面栏「导入」它即可。HEIC 会先转 JPG，同一课跨多张照片会提示是否合并。

### 按部首查字、导出 Word 与字帖

页面栏"查字"打开四步向导，把多册讲义中的字汇编成可打印文档或练字帖：

1. **选讲义**：勾选一或多册（支持"全选"、`Shift` 连选）。
2. **选部首**：基于所选讲义实际出现的部首（带字数），可"全选"（＝不按部首筛）或部分选。
3. **选单字**：列出符合条件的单字（带出现次数），**默认全选**，点字可移除/恢复；可勾"按部首排序"改此处显示顺序（不影响导出）。
4. **预览导出**：按部首分节（每部首另起一页），同部首内按讲义排序；共用同一句的几个字合并为一条（表头列这些字+出处，下一行是例句、这些字标红，可选拼音）。

导出动作：

- **打印 Word / 导出 Word**：上述"字+例句"文档（`查字-<日期>.docx`，宋体，Pages 可直接打开编辑，转 PDF 稳定）。
- **导出字帖**：把选中的**去重唯一字**生成米字格练字帖（新窗口打印 / 存为 PDF）。每字一块：首格整字 → 逐笔（已写笔画灰、当前笔粉红）→ 末尾整行描红；连续田字格、外套粗绿框、跨页补边。字序与 Word 文档中字的出现顺序一致。

# 设计与开发

以下面向后续开发：先讲清 yuwen 的设计取舍与不可破坏的约束，再给架构、关键决策理由、数据格式与开发约定。

## 设计重点

这些取舍驱动一切实现，改动前请先对齐：

1. **编辑即展示**：同一套页面既是编辑器也是投屏材料，任何编辑态都应能一键进入干净展示态（最大化 / 全文页），布局不跳动。
2. **零构建、纯静态、本地优先**：原生 ES module，浏览器直接加载，无打包、无框架、无后端，数据留在本机。新增能力尽量守住"克隆即用、`http.server` 就能跑"。
3. **正文是唯一真源**：页面只存 `mainText`，所有汉字 token、拼音、分词都由它实时派生，绝不把派生结果当真源来存。
4. **素材按「字+拼音」共享**：例词、例句、汉字配图挂在讲义级词库上按"汉字+读音"共享；每个汉字位置只存指向共享素材的**局部指针**（停留索引、隐藏名单、颜色、所选读音）。多音字天然分组。
5. **布局稳定、字号可控**：普通页三区尺寸固定；`A-/A0/A+` 是与内容无关的纯字号控制（单一基准 `38px × 字号`）。
6. **内容来源多元、但不引入后端**：手输、课本照片经技能转入、跨讲义按部首查字汇编、生成字帖——都在"静态前端 + 本地工具"内完成。

## 架构

### 模块依赖（单向、无环）

```
core  ← storage
core  ← render
core / render / storage ← events
        全部          ← main
```

| 模块 | 职责 |
|------|------|
| `src/main.js` | 启动装配：加载状态 → 绑定事件 → 首次渲染。 |
| `src/core.js` | **数据层，无 DOM**。常量、拼音/字库查询、全局 `state`、讲义/页面/汉字数据模型与上下文助手。 |
| `src/storage.js` | 持久化（IndexedDB 主存 + localStorage 兜底/迁移）、讲义 JSON 导入/导出、`yuwen-pages` 页面导入与导入时自动排版。 |
| `src/render.js` | 界面渲染，持有 `#app` 根元素；`render()` 全量重画。 |
| `src/events.js` | 事件委托与全部交互/数据操作逻辑。 |
| `src/charquery.js` | 按部首查询与导出（Word `.docx` / 打印）的纯逻辑。 |
| `src/zitie.js` | 米字格练字帖渲染（笔画数据按需取自 CDN）。 |
| `styles.css` | 界面样式。 |

### 三个核心机制

- **渲染模型**：`render()` 用模板字符串一次性重建 `#app.innerHTML`，不做局部 diff——简单优先。**所有插入的用户文本必须经 `escapeHtml` 转义**。
- **事件模型**：监听器**只在启动时一次性委托绑定**到持久的 `#app`（及 `document`）。`render()` 只替换 `#app` 的子树、`#app` 本身不变，委托对所有动态节点持续有效。单个点击分发器按 `action → 拼音 → 汉字 → 讲义 → 页面 → 空白/画布` 的优先级路由，复刻原有冒泡与 `stopPropagation` 语义。
- **数据流**：交互 → 改 `state` → `saveState()` → `render()`。即改即存。

### 状态结构

```
state.decks[]              讲义
  └ pages[]                页面
      ├ mainText           正文（唯一真源）
      ├ tokens[]           由 mainText 派生的汉字 token（index、拼音、颜色、局部索引…）
      ├ mainTextScale      字号（0.7–1.9，1 为默认）
      ├ textOnly           是否全文页
      └ images[]           页面配图
  └ lexicon{字|拼音}       讲义内按「汉字+拼音」共享的 { examples, images }
state.activeDeckId / activePageId
state.ui{…}                纯瞬时界面状态（不持久化）
```

`tokens` 始终由 `mainText` 重新分词（`tokenizePage`）。共享素材放 `deck.lexicon`，每个汉字位置只存局部指针。

### 持久化

`saveState()` 写入 payload `{ decks, activeDeckId, activePageId }`：

- **主存 IndexedDB**：库 `yuwen` / 仓库 `kv` / 键 `state`，容量足以容纳内联图片。
- **localStorage 兜底**：同一 payload 尽力镜像；超配额则忽略（以 IndexedDB 为准）。
- **迁移**：启动时 IndexedDB 无数据则从旧版 localStorage 读入。
- 导入/导出复用同一 payload 形态。

## 关键设计决策与理由

新功能容易无意破坏这些取舍，特此记录"为什么"：

- **`core.js` 不碰 DOM**：数据层可独立推理/测试（用 `node` 起 DOM 桩即可跑通启动路径）。新逻辑优先放数据层。
- **正文唯一真源 + token 派生**：避免"编辑正文后派生数据不同步"的一整类 bug。
- **素材按「字+拼音」共享**：`长|cháng` 与 `长|zhǎng` 是两组；同讲义不同页的 `春|chūn` 共享同一组例句/图片；位置级只存指针，删素材与"某处隐藏"互不影响。
- **导入不覆盖**：讲义导入→追加为新讲义并分配全新 ID（重复导入不冲突）；页面导入→追加到当前讲义。均校验结构并**只保留 `data:image/` 内联图片**，杜绝外链/脚本地址。
- **字号单一基准**：`.main-text` 统一 `38px × 字号`，`A-/A0/A+` 在长/短文、普通/全文页下含义一致；"长文"判定只再决定对齐与行高，不再改字号。（早期 70/38 双基准会让同一档字号在不同内容下大小不同，已废弃。）
- **导入自动排版（`storage.js` `autoLayout`/`isPoem`）**：导入无法真实测量渲染，用启发式——最小字号(0.7)下普通页放不下 → 全文页；字号只用两种：全文页一律 0.7，留在普通页的**诗词** 0.9、其余 0.7。诗词判定＝≥2 行且每行「1 标点≤8 字」或每行「2 标点≤16 字」。相关常量集中、可调。
- **左右分界线**：`.lesson-grid` 左侧主文区宽 `590px`（≈最小字号下 16 字一行的右边界），右侧图片区取其余。
- **Word 用 `.docx` 而非 RTF**：RTF 在 macOS 会触发"无法验证是否含恶意软件"；`.docx` 可被自带 Pages 直接打开、转 PDF 稳定。`.docx` 由内置极小 ZIP + OOXML 生成器拼装，**零第三方依赖**。
- **PDF 一律走浏览器打印**：字帖/查字文档不生成下载文件，用新窗口打印→"存为 PDF"。字帖里的田字格虚线十字用 **CSS 像素**画（SVG 缩放后是亚像素、会消失）；跨页用 `box-decoration-break:clone` 补边；打印窗口**在点击手势内同步 `window.open`** 避免被弹窗拦截。
- **字帖笔画走 CDN、不打包**：`hanzi-writer-data`（jsdelivr，unpkg 兜底），与本地 makemeahanzi 同格式；整包 20MB+，不入仓库、用时才联网。
- **部首数据离线**：`vendor/data-radicals.js`（make-me-a-hanzi），查字完全本地。
- **课本照片→文字不做后端**：浏览器沙箱无法调用 agent、读磁盘，故照片识别放在 Claude Code 技能 `textbook-photos` 完成，产出 `yuwen-pages` JSON，yuwen 只负责导入。刻意不加本地桥接/后端，守住纯静态。

## 数据格式

**页面导入（`yuwen-pages`）**——供手工或 `textbook-photos` 技能产出：

```json
{
  "format": "yuwen-pages",
  "version": 1,
  "pages": [{ "title": "春天", "text": "春天来了，\n万物复苏。" }]
}
```

`title` 可选（省略取正文开头几字）；`text` 为正文，段落用 `\n` 分隔。导入时按 `autoLayout` 自动定字号/是否全文页。参考 `示例-导入页面.json`。

**讲义导出/导入**：payload `{ decks, activeDeckId, activePageId }`（与内部持久化同形），导入追加为新讲义。

## 数据来源

- `vendor/data-chars-local.js`：浏览器加载的本地字库（`window.zDictChars`，来自 `zdict.js`）；每字按读音组织多条释义，供拼音查询与"字库例句"。加载失败回退到 `core.js` 内置小表 `FALLBACK_PINYIN`。
- `vendor/data-chars.js`：原始字库存档，运行时不加载。
- `vendor/data-radicals.js`：字→部首（make-me-a-hanzi），查字用，离线。
- 笔画：`hanzi-writer-data`（CDN，按需），字帖用。
- `.claude/skills/textbook-photos/`：把课本照片识别为 `yuwen-pages` 的 Claude Code 技能。

## 检查与开发约定

```bash
npm run check      # node --check 校验所有源码模块 + 字库包装脚本语法
```

- **守零构建**：能不加依赖就不加；必须加时保证浏览器可直接 `import`、`npm run check` 通过。改完至少跑一次它。
- **用户文本一律 `escapeHtml`** 后才拼进模板。
- **新数据逻辑进 `core.js`（无 DOM）**；渲染进 `render.js`；交互走 `events.js` 的委托分发（新增 `data-action`）。
- **改完走 `save → render`**，不要手动改 DOM 绕过重画。
- 字帖/查字等"导出"统一走浏览器打印，不生成下载文件（讲义 JSON 导出除外）。

## 当前限制与后续方向

**限制**

- 数据存于单一浏览器的 IndexedDB，无账号/云同步/后端。
- 图片以内联 `data:` URL 随讲义存储，尚无独立资源包格式。
- 整页朗读停用；多音字朗读受浏览器 TTS 限制。
- AI 配图仅生成"提示词"，未接入自动搜索/生成。
- 导入自动排版是启发式估算、非真实测量，个别页可能需手动微调。

**可能的后续**

- 资源包格式（图片与讲义分离），便于分享与版本管理。
- 更好的语音/朗读（或离线 TTS）。
- AI 配图/例句的实际接入（在不破坏"纯静态"前提下探索）。
- 字帖/查字排版的更多可调项与打印保真度。
- 导入排版从启发式走向"渲染后按实际溢出自适应"。
